# Barrie Election 2026 site

Read `PROJECT_NOTES.md` before doing any work. It holds the goal, decisions, data model, issue list, fairness standards and current status.

- Follow the fairness standards and public record rules in `PROJECT_NOTES.md` for all research and content.
- Ask the owner before starting heavy work (research rounds, builds, publishing).
- **Ask before every commit and every push.** Every push to `main` deploys the site. Show the change in the local preview, then ask before committing and before pushing (including pushing a branch). No exceptions for small fixes or internal notes; approval to make a change is not approval to commit or publish it.
- **Branches:** trivial changes (a typo, a one-line fix, a small wording or data correction) can be made on `main`. More complicated changes (features, layout or data model changes, research batches) go on a new branch that is pushed to GitHub for the owner to review. Merging a branch into `main` publishes the site, so ask before merging too.
- After each decision or completed step, update the Decisions and Steps tables in `PROJECT_NOTES.md`.
- Track open owner tasks (such as pages the owner must open manually) in `TASKS.md`.
- `PROJECT_NOTES.md`, `TASKS.md` and this file are internal and must never appear on the published site.
